# 開発計画

## 目標と参照先

[要件定義書](requirements.md)の受入条件を満たす、Windows向けのGo製CLIを実装します。開発環境は [README](../README.md)、変更・版管理の規則は [AGENTS.md](../AGENTS.md)を正本とします。

M1〜M4の実装とWindows上の受入確認が完了しています。入力収集・記録保存、`run` による実行、`status` による現在との照合、日本語・JSON出力、Windowsでの中断と子孫管理を実装しました。ライセンス・署名など配布時の判断は未実施です。

## M1: 開発基盤

- 成果物: Goモジュール、CLIの入口、日本語ヘルプ・版表示、テスト、検査・ビルドスクリプト、開発文書。
- 完了条件: 外部のGoモジュールなしで検査とビルドができ、実行ファイルの版表示が正本に一致する。未実装の処理が成功を返さず、独自の診断に引数を転記しない。
- 検証: `scripts/check.ps1` と、実行ファイルの標準出力・標準エラー・終了コードの確認。
- 依存: Go 1.27.0以上、PowerShell 7、Windows。
- 状態: 完了。
- 確認結果: 2026-10-21、Go 1.27.2・Windows/amd64・CLI 0.1.0で `scripts/check.ps1` が成功。実行ファイルでもヘルプ・版表示・引数エラー・未実装診断の出力先と終了コードを確認した。日本語と空白を含む別の作業ディレクトリでファイルを作成せず、診断へ引数の生値を出さないことを確認した。

## M2: 入力と記録の基盤

- 成果物: 入力の正規化・収集・SHA-256、実行前後の一覧と差分、記録形式、所有権を識別できる保存先、衝突しない実行ID、途中で壊れない保存と読取。
- 完了条件: 要件書4節の収集・除外・保存条件を満たす。通常ファイルとディレクトリの種類を保持し、空ディレクトリの追加・削除やファイルとの入替も差分として確認する。未対応入力・範囲外入力を子プロセスの起動前に拒否し、破損・未知形式・未完了を区別する。
- 検証: 一時ディレクトリで隠しファイル、除外領域、作業ディレクトリ外の参照、シンボリックリンク、Windowsの再解析ポイント、追加・削除・内容変更、読取・保存失敗、並行保存を確認する。実際の認証情報は使わない。
- 依存: M1。Windowsのパス・再解析ポイントと、同一ディレクトリ内での保存置換の方式を公式仕様で確認する。
- 状態: 完了（内部処理。CLIへの接続はM3）。
- 確認結果: 2026-10-22、Go 1.27.3・Windows/amd64・CLI 0.2.0で `scripts/check.ps1` が成功。隠し属性、日本語と空白、空ディレクトリ、除外、範囲外、シンボリックリンク・ジャンクション、読取不能、追加・削除・内容と種類の変更、所有確認、破損・未知形式・未完了、置換失敗、保存先移動、24件の並行保存と保存中の読取をテストした。実際の機密値は使用していない。
- 独立確認: 読み取り専用の補助担当1名が保存先移動時の誤判定候補を指摘。主担当がWindows上で `valid` となる不具合を再現し、保存先の同一性確認と回帰試験を追加して修正を確認した。
- 実装方式と制約: [入力と記録の実装](input-and-record.md)。初回の保存先初期化が競合した場合は一方が起動前に停止し得る。検証の正本は `scripts/check.ps1` と各パッケージのテスト。
- 検証対象の照合値: `212d3c0270259d464c21759b1d016adc022b0a62e34ae7a4a04fbfb98bc7c233`。`cmd`・`internal` のGoファイルと `VERSION`、`scripts` のPowerShellファイル、`go.mod` をパス順に並べ、各行を「`/` 区切りの相対パス + 半角空白 + ファイルのSHA-256小文字表記」、行間をLF・末尾改行なしとしたUTF-8一覧のSHA-256。文書とビルド生成物は対象外。

- 完了条件: 要件書3〜6節に従い、記録と出力の判定が一致する。`status` は再実行や入力の変更を行わない。入力の削除と権限不足を区別する。
- 検証: 終了コード・引数・出力・入力変更を制御できる検証用プログラムを追加する。下表の受入条件を、ビルドした実行ファイル経由で確認する。
- 依存: M2。Windowsの引数受渡しとM4のプロセス管理方式を確定する。
- 状態: 完了。`run`・`status` の引数処理、子プロセスの実行・結果保存、現在との照合、日本語・JSON出力を実装済み。
- `status` の受入確認: 2026-10-22、Go 1.27.3・Windows/amd64・CLI 0.3.0で、ビルドした実行ファイルから確認した。`valid`・`stale`・`failed`・`unstable`・`interrupted`・`unknown`、併存する事実と優先順位、内容変更・追加・削除・範囲全体の削除・種類変更、共有違反による読取不能、未完了・破損・未知形式・記録欠落・キー重複・別の作業ディレクトリ・別用途の保存先、引数エラー、JSON1件、日本語表示、終了コード0・1・2・64を確認。対象入力・記録を変更せず、検証用プログラムを再実行しないことも確認した。出力失敗はCLIの書込先を差し替えて確認した。実際の機密値は使っていない。

- 独立確認: 読み取り専用の補助担当1名が照合・判定・出力の経路、情報の保護、読み取り専用、関連テストと実装文書を静的に確認し、今回導入された不具合の指摘はなかった。実行ファイルによる受入試験と必須検査は主担当が実施した。

## M4: Windowsでの中断と受入確認

- 成果物: 中断の通知、管理対象プロセスの終了、未完了記録の扱い、Windows上の受入試験。
- 完了条件: 要件書6節と7節の全項目を満たし、中断時にも成功を推定しない。同時実行の記録が衝突しない。
- 検証: Windows上で制御した子・孫プロセスを起動し、中断、強制終了、起動直後の中断、保存失敗、大量出力、並行実行を確認する。対象のソース版・Go版と確認結果を対応付ける。
- 依存: M2・M3。中断の通知方式と、Windowsのジョブオブジェクト等による子孫管理の可否を実機で確認して採用を決める。必要な外部ライブラリの採用判断もこの時点で行う。
- 状態: 完了。
- 確認結果: 2026-10-22、Go 1.27.3・Windows/amd64（OSビルド26300）・CLI 0.4.0で専用コンソールを使って確認した。Ctrl+C・Ctrl+Breakの通知、通知を無視する子の2秒後の終了、再度の中断、起動直後の中断、checkstampの強制終了、通常終了時の孫の後片付けを確認。孫が入力を共有不可で開いた状態でも、CLIが戻った時点で子孫が終了し、再収集できることを確認した。強制終了で残った開始記録は `status` が終了コード2・`unknown` を返す。
- 採用方式: `PROC_THREAD_ATTRIBUTE_JOB_LIST` で作成時からジョブへ所属させ、`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` を設定する。中断は対象群へ `CTRL_BREAK_EVENT` を通知し、猶予後または再中断時にジョブを終了する。ジョブ内の稼働数0を確認後に再収集し、終了を確認できなければ開始記録を維持する。外部ライブラリは追加していない。公式仕様と制約は[実行と中断](input-and-record.md#実行と中断)を参照。
- 独立確認: 読み取り専用の補助担当1名が、終了要求が非同期なのに孫の終了完了を待たない競合を指摘。主担当が公式仕様を確認し、稼働数0の確認と共有不可の入力を保持する孫の試験を追加した。補助担当の追補で終了確認失敗時の終了コード64が引数エラーへ変わる箇所も指摘され、終了コードではなく問題の種類で引数エラーを判定するよう修正した。補助担当は静的確認のみ、実行ファイルの受入試験と必須検査は主担当が実施。
- 必須検査: `scripts/check.ps1` が成功。整形、静的検査、全テスト、ビルド、版表示0.4.0と正本の一致、ヘルプ表示を確認した。Goキャッシュの変更はM3欄と同じく検査プロセス内だけに限定した。
- 検証対象の照合値: `9e76c86bb5d77a30ff5719a2baac3be529968e8bbfcf6e90087e70904dd60b06`。対象と算出方式はM2欄と同じで、検証用プログラムを含む。

## 受入条件との対応

| 要件書7節 | 担当工程 | 確認する結果 |
| --- | --- | --- |
| 1: 引数・作業ディレクトリ・環境 | M3 | 空文字、空白、日本語、引用符、末尾のバックスラッシュを含む引数が保持される。環境値は保存せず、検証用プログラム内で照合する |
| 2: 終了コード | M3・M4 | 0・1・2・64・125をそのまま返す。起動後の保存失敗でも子の終了コードを変えない |
| 3: 実行後の変更 | M2・M3 | 追加・削除・変更で `stale` となる |
| 4: 実行中の変更 | M2・M3 | 終了時にも残る差分で `unstable` となる |
| 5: 不成立の記録 | M2・M3 | 読取失敗・未完了・破損・未知形式を成功にしない。状態の優先順位と併存する `issues` を確認する |
| 6: 中断・同時実行 | M2・M4 | 実行IDと記録が衝突せず、子プロセスを残さず、強制終了後は `unknown` となる |
| 7: 出力 | M3・M4 | 通常時の出力先を保ち、`--json` 時の標準出力がJSONオブジェクト1件となる。大量出力を蓄積しない |
| 8: 機密値 | M1・M2・M3 | 検証用の目印を含む引数・出力・エラー本文が記録や独自の診断に混ざらない |
| 9: 読み取り専用の照合 | M3 | `status` が子プロセスを実行せず、対象入力を書き換えない |
