# 開発計画

## 目標と参照先

[要件定義書](../要件定義書.md)の受入条件を満たす、Windows向けのGo製CLIを実装します。開発環境は [README](../README.md)、変更・版管理の規則は [AGENTS.md](../AGENTS.md)を正本とします。

今回の完了範囲はM1です。要件の判定や保存を実装済みとは扱いません。

## M1: 開発基盤

- 成果物: Goモジュール、CLIの入口、日本語ヘルプ・版表示、テスト、検査・ビルドスクリプト、開発文書。
- 完了条件: 外部のGoモジュールなしで検査とビルドができ、実行ファイルの版表示が正本に一致する。未実装の処理が成功を返さず、独自の診断に引数を転記しない。
- 検証: `scripts/check.ps1` と、実行ファイルの標準出力・標準エラー・終了コードの確認。
- 依存: Go 1.27.0以上、PowerShell 7、Windows。
- 状態: 完了。
- 確認結果: 2026-10-21、Go 1.27.2・Windows/amd64・CLI 0.1.0で `scripts/check.ps1` が成功。実行ファイルでもヘルプ・版表示・引数エラー・未実装診断の出力先と終了コードを確認した。日本語と空白を含む別の作業ディレクトリでファイルを作成せず、診断へ引数の生値を出さないことを確認した。

## M2: 入力と記録の基盤

- 成果物: 入力の正規化・収集・SHA-256、実行前後の一覧と差分、記録形式、所有権を識別できる保存先、衝突しない実行ID、途中で壊れない保存と読取。
- 完了条件: 要件書4節の収集・除外・保存条件を満たす。通常ファイルとディレクトリの種類を保持し、空ディレクトリの追加・削除やファイルとの入替も差分として確認する。未対応入力・範囲外入力を子プロセスの起動前に拒否し、破損・未知形式・未完了を区別する。
- 検証: 一時ディレクトリで隠しファイル、除外領域、作業ディレクトリ外の参照、シンボリックリンク、Windowsの再解析ポイント、追加・削除・内容変更、読取・保存失敗、並行保存を確認する。実際の認証情報は使わない。
- 依存: M1。Windowsのパス・再解析ポイントと、同一ディレクトリ内での保存置換の方式を公式仕様で確認する。
- 状態: 未着手。

## M3: 実行と有効性の照合

- 成果物: `run`・`status` の引数処理、子プロセスの実行、状態の判定、日本語・JSON出力。`run` にはM4の中断処理も組み込んで完成とする。
- 完了条件: 要件書3〜6節に従い、記録と出力の判定が一致する。`status` は再実行や入力の変更を行わない。入力の削除と権限不足を区別する。
- 検証: 終了コード・引数・出力・入力変更を制御できる検証用プログラムを追加する。下表の受入条件を、ビルドした実行ファイル経由で確認する。
- 依存: M2。Windowsの引数受渡しとM4のプロセス管理方式を確定する。
- 状態: 未着手。

## M4: Windowsでの中断と受入確認

- 成果物: 中断の通知、管理対象プロセスの終了、未完了記録の扱い、Windows上の受入試験。
- 完了条件: 要件書6節と7節の全項目を満たし、中断時にも成功を推定しない。同時実行の記録が衝突しない。
- 検証: Windows上で制御した子・孫プロセスを起動し、中断、強制終了、起動直後の中断、保存失敗、大量出力、並行実行を確認する。対象のソース版・Go版と確認結果を対応付ける。
- 依存: M2・M3。中断の通知方式と、Windowsのジョブオブジェクト等による子孫管理の可否を実機で確認して採用を決める。必要な外部ライブラリの採用判断もこの時点で行う。
- 状態: 未着手。

## 受入条件との対応

| 要件書7節 | 担当工程 | 確認する結果 |
| --- | --- | --- |
| 1: 引数・作業ディレクトリ・環境 | M3 | 空文字、空白、日本語、引用符、末尾のバックスラッシュを含む引数が保持される。環境値は保存せず、検証用プログラム内で照合する |
| 2: 終了コード | M3・M4 | 0・1・2・64・125をそのまま返す。起動後の保存失敗でも子の終了コードを変えない |
| 3: 実行後の変更 | M2・M3 | 追加・削除・変更で `stale` となる |
| 4: 実行中の変更 | M2・M3 | 終了時にも残る差分で `unstable` となる |
| 5: 不成立の記録 | M2・M3 | 読取失敗・未完了・破損・未知形式を成功にしない。状態の優先順位と併存する `issues` を確認する |
| 6: 中断・同時実行 | M2・M4 | 実行IDと記録が衝突せず、子プロセスを残さず、強制終了後は `unknown` となる |
| 7: 出力 | M3・M4 | 通常時の出力先を保ち、`--json` 時の標準出力がJSONオブジェクト1件となる。大量出力を蓄積しない |
| 8: 機密値 | M1・M2・M3 | 検証用の目印を含む引数・出力・エラー本文が記録や独自の診断に混ざらない |
| 9: 読み取り専用の照合 | M3 | `status` が子プロセスを実行せず、対象入力を書き換えない |
