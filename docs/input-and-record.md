# 入力と記録の実装

## 現在の範囲

M2の内部基盤、M3の `run`・`status`、M4のWindows中断処理を実装しました。CLIから新しい実行記録を作り、後から現在の入力と照合できます。指定範囲での判定と、保存を省略した情報・未確認の条件を日本語またはJSONで返します。

## 入力の収集

- 入力は作業ディレクトリからの相対パスです。区切りを `/` にそろえ、同じ指定をまとめます。絶対パス、範囲外、予約デバイス名、代替データストリーム、末尾の空白・ピリオドなど曖昧な指定は拒否します。
- 元の指定順（1始まり）を正規化・重複除去・並べ替えの前に保持します。重複する指定の収集に失敗した場合は、最初の指定番号を返します。原因は安全な固定区分へ変換し、入力名やOSエラーを原因に保持しません。作業ディレクトリ全体の読取失敗など、入力を特定できない場合は番号を付けません。
- 隠し属性のファイルも収集します。通常ファイルは本文を順に読みSHA-256を計算し、本文は記録しません。ディレクトリはハッシュを持たず、空でも一覧に残します。
- 各階層の `.git` と `.checkstamp` は種類を調べる前に除外し、実際に見つかった除外範囲を保存します。管理領域の直接指定は拒否します。
- 指定途中のディレクトリも1件ずつ検査します。シンボリックリンク、ジャンクションなど、`FILE_ATTRIBUTE_REPARSE_POINT` が付いた項目をすべて拒否します。特殊ファイルも扱いません。
- Windowsで大文字小文字だけが異なる複数の入力指定や、同一ディレクトリ内の名前の衝突は初版では拒否します。ディレクトリ収集時の大文字小文字だけの名前変更も差分に残します。
- 実行前の指定範囲は存在が必須です。再収集では指定入力や祖先の消失を削除として扱い、アクセス拒否・共有違反などの読取不能は一覧全体の失敗とします。収集中に列挙済みの項目が消えた場合も部分的な一覧は返しません。

[Goの `os.Root`](https://pkg.go.dev/os#Root) で作業範囲外への参照を制限します。`Root` 自体は範囲内のリンクをたどるため、単一構成要素ごとの検査と参照先へ移動しないファイルの開き方を併用しています。ディレクトリを開く際も対象の同一性を確認します。再解析ポイントの識別と開き方はMicrosoftの[再解析ポイントの操作](https://learn.microsoft.com/en-us/windows/win32/fileio/reparse-point-operations)を根拠としています。

## 保存先と形式

新規の `.checkstamp` だけに `owner` ファイルを作り、専用の保存先であることを識別します。既存の未所有領域は空でも使いません。専用領域には `runs` を作り、実行IDごとのJSONを置きます。`.gitignore` や利用先の設定は変更しません。

実行IDは暗号学的乱数16バイトの小文字16進数32文字です。同名ラベルでも別のIDとなり、排他的なファイル作成で既存記録の上書きを防ぎます。初回の所有情報の作成と別の初回呼出しが重なった場合は、他方が所有確認で安全側に停止することがあります。初期化後の並行保存では実行ごとのIDを独立して扱います。

`schema_version: 1` の主な情報は次のとおりです。

| フィールド | 内容 |
| --- | --- |
| `tool`、`command`、`run_id`、`label` | 製品名と版、操作、実行の識別情報 |
| `phase`、`status` | `started` / `completed` と実行前後の入力に基づく判定 |
| `started_at`、`finished_at`、`child_exit_code` | UTC日時と子プロセスの終了コード。開始時の未確定値は `null` |
| `conditions` | 作業ディレクトリ、解決済み実行ファイル、引数列のSHA-256 |
| `coverage` | 保存を省略した情報と、未確認の条件 |
| `before`、`after` | 指定範囲、入力一覧、除外範囲。実行後の読取失敗は `after: null` |
| `changes`、`issues`、`interrupted` | 入力の差分、併存する事実と日本語の固定説明、中断の有無 |

引数列はJSON文字列配列の表現をSHA-256に渡すため、空文字・引用符・空白・末尾のバックスラッシュも境界を保ちます。引数の生値、環境変数の値、子の出力、入力の本文を記録用の型に持たせません。ラベル、パス、実行ファイルの解決先は要件で定める保存対象です。

開始記録は `unknown` とし、完了日時と終了コードがない記録を成功扱いにしません。完了時は `unknown`、`interrupted`、`failed`、`unstable`、`valid` の順で判定し、併存する事実を `issues` と差分に残します。現在との照合で判断する `stale` は保存記録へ書き戻しません。

## 保存と読取の失敗

開始・完了とも同じ `runs` 内の固有の一時ファイルへJSONを書き、`Sync`・`Close` 後に `Root.Rename` で置換します。実行中の記録へ直接追記・切詰めをしません。使用したGo 1.27.3のWindows実装は、ハンドルを基準にした名前変更を使います（[GoのWindows実装](https://go.dev/src/os/root_windows.go)、[Microsoftのファイル名変更の仕様](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/ns-ntifs-_file_rename_information)）。電源断・機器障害に対する永続性まで保証する方式ではありません。

保存先の所有情報とディレクトリの同一性を読取・保存の前後で確認します。保存先が移動・交換されていた場合、古いハンドルだけを信頼して成功を返しません。完了保存に失敗すると返す結果は `unknown` となり、取得済みの子の終了コードは保持します。置換前の失敗では開始済みの記録を残します。

読取では未知の形式、必須情報の欠落、未知のフィールド、重複したJSONキー、一覧・差分・判定の矛盾を拒否します。空や切断された記録は破損、形式の版が違う記録は未対応、正常な開始記録は未完了として区別します。1件64MiB以上の記録は保存・読取を拒否し、記録の破損による過大な読み込みを抑えます。

読取専用の開き方は保存先を作らず、開始記録の作成も許しません。OSのエラー、入力や引数の生値、読み込んだJSONの本文を独自の診断へ転記しません。

## 実行と中断

`run --label <名前> --input <対象> [--input <対象> ...] [--json | --json-summary] -- <実行ファイル> [引数...]` を受け付けます。空でないラベル、1件以上の入力、区切りの `--` とコマンドが必須です。ラベルの重複、JSONモードの重複・併用、未知のオプションは拒否します。区切り以降の空文字や `--json`、`--json-summary` などは子の引数のまま渡します。

起動前の入力エラーは、指定番号と不存在・読取不能・未対応入力などの原因区分を説明し、子を起動していないことを明示します。不正な範囲と管理領域の直接指定は `invalid_arguments`・終了コード64、それ以外の収集失敗は `input_collection_failed`・終了コード125を維持します。標準エラーと両JSONモードの `issues` に同じ説明を1件だけ返し、`child_exit_code` は `null`、実行IDは空とします。アクセス拒否か共有違反かなど、確定できない詳細な原因は断定しません。

入力を収集し、`exec.LookPath` で通常の実行ファイル（`.exe` / `.com`）を解決してから開始記録を保存します。保存成功後だけ子を作成します。スクリプトの暗黙実行や、検索時に安全でない作業ディレクトリへの暗黙の解決は行いません。Windows APIへ渡すコマンド行は、Go標準の `syscall.EscapeArg` で引数ごとに構成します。これはGoやMicrosoftのCランタイムと同じ規則で引数を読む実行ファイルを対象とし、独自の解析規則を持つ実行ファイルでの解釈までは保証しません。

`CreateProcessW` の環境引数を `NULL` にして親の環境をそのまま継承し、開始時の作業ディレクトリを渡します。通常CLIでは標準入出力のハンドルだけを複製して渡し、ジョブなどの内部ハンドルは継承させません。通常時は子の出力先を保ち、`--json` と `--json-summary` では両出力を標準エラーへ向けます。出力を結果のために蓄積しません。ファイル以外の書込先を使う内部呼出しでは、固定容量のパイプと `io.Copy` で転送します。

Windowsの[プロセス作成属性](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute)の `PROC_THREAD_ATTRIBUTE_JOB_LIST` で、子を作成時から専用ジョブへ所属させます。ジョブには `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` を設定し、checkstampの強制終了でも管理下の子孫を終了します。ジョブの設定や起動に失敗したときは管理なしで実行せず、開始記録を完了へ変更しません。

子は `CREATE_NEW_PROCESS_GROUP` で起動します。Ctrl+C / Ctrl+Breakを受けたら、そのプロセス群へ `CTRL_BREAK_EVENT` を送り、2秒の猶予を置きます。再度の中断または猶予の終了でジョブ全体を終了します。[コンソール通知](https://learn.microsoft.com/en-us/windows/console/generateconsolectrlevent)は同じコンソール内の対象だけへ届くため、コンソールがない・子が通知を無視する場合もジョブによる終了を行います。

直接の子が終了した場合も、残った子孫を `TerminateJobObject` で終了します。[終了要求は非同期](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-terminateprocess)なので、要求前に[ジョブ内のプロセスを列挙](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_process_id_list)してハンドルを保持し、所属も確認します。再中断・猶予切れにも同じ処理を使います。要求後は全ハンドルの終了と稼働数0を共通の5秒期限で確認してから入力を再収集します。稼働数だけで先へ進み、終了途中の孫が保持する入力を読めなくなる問題を防ぎます。

列挙後の新しいプロセスを取りこぼした可能性があれば、累計プロセス数の変化から終了確認の失敗とします。列挙・所属確認・待機の失敗も同様に扱い、開始記録を維持して結果を `unknown` とします。管理範囲は[ジョブに所属する子孫](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)です。WMIや別サービス経由で起動する外部プロセスは含みません。

取得した終了コードは非0でもそのまま返します。再読取失敗は `after: null`、完了保存失敗は `record_write_failed` として `unknown` を返します。起動後の失敗や結果JSONの出力失敗でも取得済み終了コードを変更しません。終了コードを取得できなければ125を返し、開始記録を維持します。`--json` の結果は実行情報、日時、条件、一覧、差分、`issues`、中断の有無を含み、起動前などの取得不能な値は `null` です。引数エラーもいずれかのJSONモードが指定されていればJSON1件を返し、不正な引数の生値は返しません。

## 現在の入力との照合

`status <実行ID> [--json | --json-summary]` は同じ作業ディレクトリの専用保存先を読み取り専用で開きます。実行IDは小文字16進数32文字のみを受け付け、パスや未知のオプションとして解釈しません。JSONモードは実行IDの後ろにいずれか1回だけ指定します。

記録の読取が成立した場合だけ、記録済みの入力範囲を再収集します。入力がなくなった場合は差分、アクセス拒否・共有違反や未対応の種類は読取不能として区別します。状態の優先順位は `unknown`、`interrupted`、`failed`、`unstable`、`stale`、`valid` です。実行時の失敗や未完了を、現在の入力が読めるという理由で成功へ変更しません。判定と併存する事実は結果の `issues` に残します。

`--json` のオブジェクトには保存記録に対応する実行情報と、次の照合情報を含めます。

| 項目 | 内容 |
| --- | --- |
| `tool`、`command` | 照合したCLIの製品名と版、`status` |
| `status`、`record_status`、`record_tool` | 現在を含む判定、記録時の判定、記録を作成した製品名と版 |
| `before`、`after`、`current` | 開始時、終了時、現在の入力一覧 |
| `changes` | 記録された実行前後の差分。変更せず返す |
| `current_changes` | 終了時の一覧から現在への差分。終了時の一覧がなければ開始時からの差分 |
| `issues` | 記録時の事実と、照合中に確認した変更・読取不能など |

`run_id` は照合を依頼されたIDです。記録を読み取れない場合の `label`、`record_status`、`record_tool`、実行日時、終了コード、実行条件、記録済み一覧は `null` にします。読取不能な現在の一覧も `current: null` とし、削除によって空になった一覧と区別します。差分と `issues` は空の場合も配列で返し、`coverage` には保存を省略する情報と未確認の条件を常に含めます。引数エラーでもいずれかのJSONモードが指定されていれば1件のJSONを返しますが、不正な実行IDの生値は返しません。

通常表示は判定、取得済みの終了コード、確認事項、実行前後と現在の差分、有効性の範囲を標準出力へ返します。確認不能の場合は標準エラーにも固定の診断を出します。結果出力の書き込みに失敗した場合は、成功を返さず終了コード2とします。引数エラーは64を維持します。照合結果は保存記録へ書き戻しません。

## 短いJSON出力

`run` と `status` の `--json-summary` は次の8項目だけを返します。詳細を含む既存の `--json` と保存形式は変更しません。両方のオプションがある引数エラーでは要約を返します。

| 項目 | 内容 |
| --- | --- |
| `schema_version` | JSON形式の版。現在は1 |
| `command` | `run` または `status` |
| `run_id` | 実行ID。未発行や不正な引数の場合は空文字 |
| `status` | 詳細出力と同じ判定 |
| `child_exit_code` | 取得した子の終了コード。未取得は `null` |
| `change_count` | 実行前後の変更件数。終了時の一覧を取得できなければ `null` |
| `current_change_count` | 最後の記録から現在への変更件数。現在の一覧が未確認、または `run` なら `null` |
| `issues` | 詳細出力と同じ問題の識別子・日本語の説明。空でも配列 |

件数は追加・削除・変更されたパスを各1件とし、ファイルだけでなく空ディレクトリや種類の変更も含めます。開始記録が未完了でも、現在の入力を読めれば開始時からの `current_change_count` を返しますが、`unknown` の判定は維持します。

実行前後の入力一覧と差分の明細は、要約モードでも `.checkstamp/runs/<実行ID>.json` に保存します。現在の入力一覧と差分は保存記録へ書き戻さず、`status --json` で取得できます。要約への切替で、入力の収集・照合範囲や終了コードは変えません。

## 確認方法

通常の `scripts/check.ps1` が入力・記録のテストも実行します。一時ディレクトリと検証用の値だけを使い、隠し属性、日本語と空白、空ディレクトリ、追加・削除・内容と種類の変更、リンクとジャンクション、読取不能、所有確認、破損・未知形式・未完了、保存先移動、置換失敗、24件の並行保存と保存中の読取を確認します。

`internal/cli/status_test.go` は実行ファイルをビルドし、`status` の判定、優先順位、終了コード、日本語・JSONの出力、入力全体の削除と共有違反による読取不能を確認します。照合前後で名前・種類・通常ファイルの本文と更新日時を比較し、入力・保存記録・別用途の保存先が変わらないことを確認します。記録の実行条件には、起動されると印を作る検証用プログラムを指定し、再実行がないことも検査します。実際の機密値は使いません。

`internal/cli/run_test.go` はCLIと `testdata/command` の検証用プログラムをビルドします。引数の境界、環境、作業場所、終了コード0・1・2・64・125・4294967295、入力の追加・削除・変更、起動前の拒否、再読取・保存・結果出力の失敗、16MiBの出力、8件の並行実行を確認します。専用コンソールでCtrl+C・Ctrl+Break、通知無視と2秒後の終了、再度の中断、起動直後の中断、親の強制終了、通常終了時の孫の後片付けを確認します。孫1件と32件がそれぞれ入力を共有不可で保持した状態から、CLIが戻った時点でプロセスが終了し、入力を読めることを検査します。保存記録と結果JSONも比較します。

要約は1,832ファイルとその全削除を実行ファイル経由で試し、`run`・`status` の出力が1KiB以内であること、詳細な一覧・差分を失わないこと、子の出力先と終了コードを保つことを確認します。`status` の既存の状態・優先順位・破損などの試験でも、要約の判定・問題・件数と `null`、読み取り専用を確認します。引数の重複・併用と、出力失敗時の終了コードも検査します。
