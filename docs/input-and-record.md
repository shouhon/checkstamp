# 入力と記録の実装

## 現在の範囲

M2の内部処理を実装しました。`run`・`status` への接続、子プロセスの起動、現在の入力との照合、結果JSONの標準出力はM3、中断の処理はM4の対象です。内部の `valid` は実行前後の一覧と渡された終了コードに基づく値で、現在のCLIが検証コマンドを実行済みという意味ではありません。

## 入力の収集

- 入力は作業ディレクトリからの相対パスです。区切りを `/` にそろえ、同じ指定をまとめます。絶対パス、範囲外、予約デバイス名、代替データストリーム、末尾の空白・ピリオドなど曖昧な指定は拒否します。
- 隠し属性のファイルも収集します。通常ファイルは本文を順に読みSHA-256を計算し、本文は記録しません。ディレクトリはハッシュを持たず、空でも一覧に残します。
- 各階層の `.git` と `.checkstamp` は種類を調べる前に除外し、実際に見つかった除外範囲を保存します。管理領域の直接指定は拒否します。
- 指定途中のディレクトリも1件ずつ検査します。シンボリックリンク、ジャンクションなど、`FILE_ATTRIBUTE_REPARSE_POINT` が付いた項目をすべて拒否します。特殊ファイルも扱いません。
- Windowsで大文字小文字だけが異なる複数の入力指定や、同一ディレクトリ内の名前の衝突は初版では拒否します。ディレクトリ収集時の大文字小文字だけの名前変更も差分に残します。
- 実行前の指定範囲は存在が必須です。再収集では指定入力や祖先の消失を削除として扱い、アクセス拒否・共有違反などの読取不能は一覧全体の失敗とします。収集中に列挙済みの項目が消えた場合も部分的な一覧は返しません。

[Goの `os.Root`](https://pkg.go.dev/os#Root) で作業範囲外への参照を制限します。`Root` 自体は範囲内のリンクをたどるため、単一構成要素ごとの検査と参照先へ移動しないファイルの開き方を併用しています。ディレクトリを開く際も対象の同一性を確認します。再解析ポイントの識別と開き方はMicrosoftの[再解析ポイントの操作](https://learn.microsoft.com/en-us/windows/win32/fileio/reparse-point-operations)を根拠としています。

## 保存先と形式

新規の `.checkstamp` だけに `owner` ファイルを作り、専用の保存先であることを識別します。既存の未所有領域は空でも使いません。専用領域には `runs` を作り、実行IDごとのJSONを置きます。`.gitignore` や利用先の設定は変更しません。

実行IDは暗号学的乱数16バイトの小文字16進数32文字です。同名ラベルでも別のIDとなり、排他的なファイル作成で既存記録の上書きを防ぎます。初回の所有情報の作成と別の初回呼出しが重なった場合は、他方が所有確認で安全側に停止することがあります。初期化後の並行保存では実行ごとのIDを独立して扱います。

`schema_version: 1` の主な情報は次のとおりです。

| フィールド | 内容 |
| --- | --- |
| `tool`、`command`、`run_id`、`label` | 製品名と版、操作、実行の識別情報 |
| `phase`、`status` | `started` / `completed` と実行前後の入力に基づく判定 |
| `started_at`、`finished_at`、`child_exit_code` | UTC日時と子プロセスの終了コード。開始時の未確定値は `null` |
| `conditions` | 作業ディレクトリ、解決済み実行ファイル、引数列のSHA-256 |
| `coverage` | 保存を省略した情報と、未確認の条件 |
| `before`、`after` | 指定範囲、入力一覧、除外範囲。実行後の読取失敗は `after: null` |
| `changes`、`issues`、`interrupted` | 入力の差分、併存する事実と日本語の固定説明、中断の有無 |

引数列はJSON文字列配列の表現をSHA-256に渡すため、空文字・引用符・空白・末尾のバックスラッシュも境界を保ちます。引数の生値、環境変数の値、子の出力、入力の本文を記録用の型に持たせません。ラベル、パス、実行ファイルの解決先は要件で定める保存対象です。

開始記録は `unknown` とし、完了日時と終了コードがない記録を成功扱いにしません。完了時は `unknown`、`interrupted`、`failed`、`unstable`、`valid` の順で判定し、併存する事実を `issues` と差分に残します。現在との照合による `stale` はM3で追加します。

## 保存と読取の失敗

開始・完了とも同じ `runs` 内の固有の一時ファイルへJSONを書き、`Sync`・`Close` 後に `Root.Rename` で置換します。実行中の記録へ直接追記・切詰めをしません。使用したGo 1.27.3のWindows実装は、ハンドルを基準にした名前変更を使います（[GoのWindows実装](https://go.dev/src/os/root_windows.go)、[Microsoftのファイル名変更の仕様](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/ns-ntifs-_file_rename_information)）。電源断・機器障害に対する永続性まで保証する方式ではありません。

保存先の所有情報とディレクトリの同一性を読取・保存の前後で確認します。保存先が移動・交換されていた場合、古いハンドルだけを信頼して成功を返しません。完了保存に失敗すると返す結果は `unknown` となり、取得済みの子の終了コードは保持します。置換前の失敗では開始済みの記録を残します。

読取では未知の形式、必須情報の欠落、未知のフィールド、重複したJSONキー、一覧・差分・判定の矛盾を拒否します。空や切断された記録は破損、形式の版が違う記録は未対応、正常な開始記録は未完了として区別します。1件64MiB以上の記録は保存・読取を拒否し、記録の破損による過大な読み込みを抑えます。

読取専用の開き方は保存先を作らず、開始記録の作成も許しません。OSのエラー、入力や引数の生値、読み込んだJSONの本文を独自の診断へ転記しません。

## 確認方法

通常の `scripts/check.ps1` が入力・記録のテストも実行します。一時ディレクトリと検証用の値だけを使い、隠し属性、日本語と空白、空ディレクトリ、追加・削除・内容と種類の変更、リンクとジャンクション、読取不能、所有確認、破損・未知形式・未完了、保存先移動、置換失敗、24件の並行保存と保存中の読取を確認します。
